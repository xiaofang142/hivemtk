# Bug Fix: 爬取任务租户贯通与持久恢复

- Assessment: [assessment.md](assessment.md)
- Date: 2026-11-20
- Status: 代码、定向回归、最终完整门禁及生产迁移和发布核验完成。

## 修复行为

手动同步与重试均通过现有异步执行器保留租户值，解除 HTTP 请求取消对后台任务的影响。重试支持 failed 和 partially_failed；原批次保持审计记录，新批次保留租户与重试计数。

批次先在数据库声明同源串行租约，再执行最长三十分钟的爬取。租约为三十五分钟，所有完成写入检查 token 与来源，过期 worker 不能覆盖后继任务。批次与来源摘要同一事务完成；状态更新失败返回错误并保留可恢复状态。cron 先恢复 pending 和过期 running，再处理到期自动源。

新增页面检查点按 tenant/source/URL 哈希唯一定位文档与知识库。准备页面、正文更新和分片失效均检查错误；同步处理到索引与文档状态成功后，再提交页面完成哈希。QA 候选与 QA 完成哈希同一事务落库，空候选也持久记完成。失败保留错误，下一次同 hash 仍会执行。持久完成记录不能代替内存索引：新进程恢复时重建索引，已完成 QA 不重复生成。

新增同步错误返回入口，保留原有 void 调用接口供既有上传等路径使用。删除爬虫已消除的两个裸协程基线豁免；无新增中间件或外部服务。

最终复核另见 [assessment-followup.md](assessment-followup.md)：同步爬取向量阶段使用新增 `EmbedBatchContext`，使租户、批次截止时间和取消到达向量服务。旧 `EmbedBatch` 及普通异步导入调用保留原行为。新增回归先确认三项上下文断言失败，再验证修复通过。

集成上游修复后，可信系统扫描收窄到来源租户，普通缺租户或错租户请求继续拒绝。QA 和候选写入失败在检查点事务内同步标记文档 failed；同步读取或 processing 状态写入失败也经有界失败入口保留原因。新增集成红测先复现这些缺口，修复后与上游既有回归共同通过。

同步处理返回后再读取文档终态，只有 indexed 才进入 QA 和完成检查点。实际回归先复现 processing 仍被计为完成，再验证拒绝并保留可重试失败。删除未被生产调用的旧上下文辅助函数，由控制器实际入口验证取消后的租户、trace 和截止时间。

## 变更范围

模型增加批次租约与页面检查点，经现有 ExtraModels 启动迁移路径注册。仓储负责声明、围栏、页面关联、候选与检查点事务；服务负责索引/QA 编排；控制器只启动现有执行器。未新增对外路由。

定向测试使用真实专用 PostgreSQL，网络/向量/模型返回使用明确合成数据，未向生产客户发送消息。
