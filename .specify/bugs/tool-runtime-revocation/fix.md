# Bug Fix: 权威工具状态与实际执行准入接通

- Slug: tool-runtime-revocation
- Fixed: 2026-11-20
- Assessment: [assessment.md](assessment.md)

## Changes

- 新增只读权威准入仓储。每次实际执行检查可信租户及 `AIToolConfig`；持久化 OpenAPI/MCP 再检查来源 ID、启用状态及捕获的执行配置。无配置行保留内置默认策略，缺表、缺数据库、查询失败及缺租户不能冒充无配置。
- 全局生产执行器明确装配准入，放在重试内部的实际执行前；直接执行持久化工具也检查来源，不依赖缓存清理、重启或进程间通知。
- OpenAPI 导入落库后按持久化行重建工具，不再将租户导入注入全局自动提供者；启动重建使用同一权威依赖。生产 SSRF 传输与校验保留。
- MCP 重发现使用注册表原子替换，刷新完整处理器及客户端；旧 ID、旧凭据或旧执行配置不能因同名重建继续调用。统计回写不改变执行版本。
- MCP 发现失败保留配置保存契约，但响应明确本次 `error` 状态，不再返回空状态或旧 `ok`；删除后下一次准入即拒绝，已准入在途调用允许完成。
- 权威实现经低依赖 `toolruntime.Authority` 端口显式注入 AI 层，由应用与服务装配仓储；不反向导入仓储、不放宽依赖门。未装配端口的持久化工具拒绝实际执行，MCP 连发现请求也不发出。
- 生产注册表的权限包装同时检查准入，覆盖 MCP 服务端及注册表直接执行内置工具的路径；注册包装采用原子替换，不依赖调用者一定经过全局执行器。
