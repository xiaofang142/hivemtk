# Bug Assessment: FA-14 客户合并保留同意事实与暂停

- **Slug**: customer-consent-alias
- **Created**: 2026-11-20
- **Source**: 外层 `docs/未完成任务清单.md` FA-14
- **Verdict**: valid
- **Severity**: high

## Report

客户合并删除次客户，却未关联其原 one_id 的授权事件和暂停偏好。合并后的客户 360 与发送闸口只读主身份，次身份的撤回或暂停会消失，默认 revocation_only 可能恢复外发。

## Reproduction

专用 PostgreSQL 上的真实 MergeCustomers、ContactConsentService 与发送管线已通过仓库外 Go overlay 复现。主身份 grant，次身份分别为较早的 revoke 或无授权事件的渠道暂停；合并后错误返回 granted、时间线或偏好缺失、进程内测试适配器被调用一次。事件合并前后快照相等，根因是关联缺失。未发送任何外部消息。

## Root Cause

`service/customer.go` 只迁移既有客户附属表；`repository/contact_consent_repo.go` 所有查询只匹配单个 one_id。`CheckSendConsent` 在事件不存在时提前返回 missing，连独立暂停也无法生效。

## Remediation Contract

- 追加租户内、无方向的身份关联边；事件和偏好保留原 one_id、ID、发生时间、证据及其余字段。关联边按字典序存储，唯一键为租户和两端身份，不移动或复制授权事实。
- 客户合并先在同一事务锁住两行客户，再写关联、迁移附属记录并删除次客户。关联写入或后续删除失败全部回滚。已删除次客户再次合并沿用明确错误口径，不增加事实或关联；链式、反向和重复关联不丢失身份。
- 同一原身份维持原规则：相关目的/渠道内最新事件生效，精确渠道偏好覆盖全渠道偏好，过期暂停失效。
- 关联身份之间任何有效 revoke 优先，其次任何有效暂停；其他身份的 grant 或恢复不覆盖它。全部身份均无有效否定时，有 grant 则 granted，否则 missing。暂停无需先有 grant；不改变现有正常 missing 的两种发送模式。
- 客户 360 的时间线、偏好列表和发送闸口使用同一身份解析；返回原始 one_id 以保留来源。别名、事件、偏好查询失败均拒发，不把缺表或故障当无历史。
- 所有别名与事实读写显式限定租户；多租户缺上下文和跨租户合并均拒绝，即使相同 one_id 在别的租户存在关联也不可见。

## Implementation Plan

1. 固化真实合并、时间线、偏好、发送闸口及不可变快照的失败回归。
2. 增加关联模型和启动迁移，仓储用现有 GORM 查询遍历去重的身份连通组；不新增 Raw/Exec 白名单。
3. 将关联写入既有客户事务，服务聚合各原身份状态；补重复/链式、回滚、租户、查询故障回归。
4. 运行定向和冻结全量门禁，记录真实证据；双远端发布并走链 A，核对迁移、二进制、健康与回滚点后关闭精确清单行。

## Alternatives and Boundaries

拒绝直接改写事件 one_id（会改变历史证据）、复制事件（会制造事实）以及简单取合并后全局最新事件（另一身份的较晚 grant 会覆盖撤回）。本轮沿用既有界面和路由，通过原时间线/偏好 API 验证客户 360 与发送闸口的一致性，不增加外部依赖。历史已合并且未记录身份来源的客户无法凭空补齐关联，不伪造历史映射。
