# FA-AGENT-UI-03 · 智能体部分保存恢复

- 日期：2026-11-20
- 结论：valid；原组件 8 项业务用例中 7 项失败，另加的 10 项边界用例中 4 项暴露未知身份、错误 ID 和恢复期间换编码问题；均保留真实红灯后修复。
- 根因：`Edit.vue` 在主记录提交后捕获并吞掉绑定替换错误，随后无条件成功提示和导航；创建得到的 ID 未保留，重试再次走创建分支；没有回读确认。

## 方案论证

采用可见、可恢复的部分完成协议，保持现有两个写接口，不把它们伪称为原子事务。主记录和绑定分别回读；明确改绑时才处理绑定，保留 UI-02 对未知、读取失败及未改绑定的保护。失败保持表单、所选绑定和已知 ID，显示具体失败阶段，原保存按钮可重试。已保存的同一主配置及已生效的同一绑定通过回读恢复，避免重复提交。

创建沿用数据库唯一 `agent_code` 作为业务身份。新增租户隔离的精确编码查询：首次创建前拒绝已有编码；创建请求已尝试但回执未知时，只恢复与本次原始配置完全一致的记录。未知或不匹配不写绑定、不报成功。编码未找到才可再尝试相同编码，数据库唯一约束阻止两个主记录。恢复期间不允许换编码绕过未确认请求；已知 ID 后只对该记录更新。此方案不新增数据库列或迁移，不采用列表模糊检索、TTL 或猜测最新记录。

不同方案：合并事务接口可提供更强原子性，但需要改变现有两个资源的更新契约；为本次页面恢复引入持久化幂等表过大。选择保留两个资源并明确部分状态。普通字段保存且绑定未知/未改时仍不读写绑定，不虚称已同步未知选择。并发操作者在最终回读后继续修改的情形不在本次引入版本锁。

## 验收与范围

挂载真实 Vue/ElementPlus 组件，覆盖创建及更新绑定拒绝、重试、创建响应丢失、绑定响应丢失、主记录及绑定回读不一致/失败、已有编码冲突、查询故障、重复点击、路由离开。真实 PostgreSQL 验证精确查询的租户隔离及唯一编码；本地真实浏览器逐元素验证失败可见和恢复，第三方信号不外发。新增文案九语种对齐。

仅触及编辑保存、精确查询的 controller/service/API、对应测试及报告；不改 UI-02 的绑定读取契约、不重写其它页面。完成完整仓库门禁及 API/SPA 发布核验后才销项。
