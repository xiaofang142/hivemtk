## 保存协议

保留主记录与绑定两个资源的接口。保存过程按主记录、身份查询、回读确认、绑定同步显示失败阶段；失败保持表单和已知 ID，不跳转，不提示整体成功。只有主配置回读匹配、明确改动的绑定集合回读匹配、最后主配置再次匹配时才成功。

创建前新增租户隔离的精确编码查询。首次发现已有编码拒绝创建；请求尝试后回执丢失，仅恢复编码及原始配置全部匹配的记录。只有显式 null 表示未找到，未知响应、查询故障、错误 ID 或不匹配配置均拒绝继续。恢复期间不能更换编码规避既有请求。数据库原唯一编码约束负责防止并发生成第二条记录，未增加迁移。

已确认写入的相同配置通过回读跳过重复主写；绑定提交回执丢失时回读实际集合，已生效则可确认成功。绑定失败时重试只补未完成部分。保留 UI-02 对未知、读取失败及未改绑定的保护，普通字段保存不隐式覆盖绑定。重复点击、路由切换及卸载通过保存状态和代际检查阻止后续写入。

首轮完整 audit 将动态拼接的四条阶段翻译键判为孤儿词条。已将阶段到翻译键改成显式映射，保留提示语义，不修改扫描器或基线；补跑完整 audit 和受影响的前端检查。

## 范围与边界

第三方故障为本地内存 HTTP 信号，浏览器未连接生产数据库或外发；PostgreSQL 身份及字段契约另行验证。没有将两个写接口描述为事务，也没有引入跨浏览器持久化恢复日志或并发版本锁；恢复凭据保存在当前编辑器，重开后已有编码会拒绝再次创建，须从列表编辑该记录。九语种新文案保持相同键和占位符。旧 UI-01/UI-02 测试及夹具补齐新查询和真实回读，不降低原断言。
