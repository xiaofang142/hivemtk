# Bug Assessment: 保留每个账号与行业及角色授权的配对关系

- **Slug**: crm-account-role-pairing-20261125
- **Created**: 2026-11-25
- **Source**: `docs/未完成任务清单.md` §3.29 `CRM-20261125-24`
- **Verdict**: valid

## Report

`Resolve` 将各账号的可见行业并入全局 `Industries`，任一 owner 角色令全局 `OnlyOwned=true`；`ToFilter/CanAccess/AllowsWrite` 按独立账号集合与行业集合组合过滤。A 账号只许行业甲、B 账号只许行业乙时，A/乙、B/甲可能被组合放行；混合 owner/viewer 又可能错误收窄合法账号。识别码被并入账号集合，码重置后可继续充当 ACL。

## Scope

- `CustomerDataScope` 增加逐账号配对规则（账号引用 + 行业集合 + 角色条件）。
- `Resolve` 按每条授权保留配对，识别码仅作为账号解析引用，不直接作为 ACL 键。
- `CanAccess/AllowsWrite/ToFilter` 在配对存在时按配对判定；旧字段作为兼容回落。
- 真实 PG/纯函数测试：A/甲、B/乙允许，交叉拒绝；owner/viewer 混合不互扩；码重置、撤权、管理员正例。

## 2026-11-26 补充调查

- 原 `ListScoped` 在内存配对过滤前依赖仓储默认分页，探测虽请求 10,000 条，实际被限为 20 条，后续分页、总数及导出存在漏行风险。配对必须在 SQL 的 count 与 page 两个查询之前生效。
- 空授权叠加调用方的 `source_account_id` 过滤会重新获得账号；行业数组的 `null`/空白元素被错误接受；缺租户的管理员分支和 owner 零用户身份也需要显式拒绝。
- 客户记录详情、360、通信记录三个读取入口未解析 CRM 范围。联系人、供应商、服务商的列表、360 聚合和实体去重只验证父客户，未逐实体过滤账号；修改和删除亦未验证旧实体账号。
- 渠道账号冗余识别码不等于当前权威码。当前码、有效期内旧码、跨账号/租户冲突、多账号共用渠道及孤儿授权须独立验证，不能依赖通用识别码查询任取首条。
- 复核另发现：权威码所属渠道没有账号行时，仅按候选账号计数会误将其他渠道的冗余同码视为唯一。有效权威码声明必须单独保留，并验证唯一候选账号与声明的租户、渠道同时一致；不能因权威渠道缺少账号而回退给其他渠道。
