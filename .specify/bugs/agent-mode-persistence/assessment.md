# FA-AGENT-UI-01 智能体模式保存评估

- 日期：2026-11-20；结论：有效，真实组件已复现保存字段遗漏；真实 PostgreSQL/HTTP 已复现未知模式写入及独立运行服务缓存旧模式。
- 页面 `Edit.vue` 已有 active/passive 选择器，详情加载也保留 agent_mode，但创建和修改共用的保存对象遗漏该字段。
- 控制器创建接收 agent_mode，更新只复制非空字符串，且忽略 JSON 解析错误；服务层未限制模式枚举。仓储已写入 agent_mode，LoadContext 已读取模式，生命周期运行入口按该上下文分派。

## 方案论证

沿用现有模式控件，在共用保存对象中传入 agent_mode。服务层作为管理及内部调用的共同边界，只允许 active/passive；创建时省略模式继续默认 passive，兼容现有调用。修改明确传入空值或未知值时拒绝，省略字段保留原模式；控制器拒绝解析错误，避免非字符串被忽略。校验在写库、版本递增和缓存失效前完成。保留生命周期对历史异常模式及主动依赖未装配时的被动兜底。

备选：仅增加前端字段。放弃，直调 API 仍可持久化未知模式。备选：运行时把未知模式映射为主动。放弃，扩大对外执行风险且无法修复保存契约。无需改表、迁移、依赖、运行路由或界面布局。

进一步按生产装配分离管理与运行服务，复现修改后运行入口仍使用旧模式。生命周期入口改用专门的权威上下文读取适配器，每次运行绕过本地上下文缓存，复用同一字段映射；其他使用者继续沿用原缓存契约。共享服务实例或缩短 TTL 无法覆盖独立实例，不采用。已经开始的生命周期按取得的上下文完成，新运行按最新持久化模式分派；读取失败拒绝分派。
