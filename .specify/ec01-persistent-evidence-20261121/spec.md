# Feature Specification: EC-01 持久能力证据

**Status** Draft · 2026-11-21
**Scope authority** 外层未来任务清单 §7.1.8、M01、§7.2.2、RV01/RV04/RV10；本轮授权限本地工程。

## User Scenarios & Testing

### US1 管理员查询动作格（P1）

给定本租户已登记动作格，查询某店只返回该店状态、scope、证据覆盖、版本、到期和明确拒绝原因。请求中的店铺标识用于查询，不能建立归属。无记录、外租户、过期、撤权、模拟证据、存储不可用时保持阻塞，摘要不包含凭证或证据原文。

### US2 执行按资源重新裁决（P1）

桥账号或平台订单先按租户、来源、产品和资源绑定到唯一店铺，再查逐动作格与当前连接。无绑定、错店、动作或载体不匹配、证据或连接不匹配均拒绝。凭证无法与实际执行目标绑定的 HTTP 载体继续阻塞。逐动作状态要求不使用持久布尔代替实时预检。

### US3 历史记录消费（P1）

混合文本、图片或不同账号的历史候选逐条按已锁定的数据库行重查。撤权已提交后相应候选不得认领；其他可用候选仍可处理。缺失映射、存储错误与拒绝不得消耗历史租约/预算或更改成功事实。

## Requirements

- FR-001 持久记录精确来源身份及精确能力证据，强制租户边界和唯一来源身份。
- FR-002 连接、映射和证据必须相符且有效；每次读取重查，版本或授权变化导致旧证据失效。
- FR-003 仅可使用受控服务端证据来源；客户端与模拟数据不可取得真实运行等级。此切片不引入生产取证入口。
- FR-004 原有管理员只读接口与既有执行路径应使用持久裁决，系统范围和数据库故障默认拒绝。
- FR-005 历史队列在原认领事务中读授权，不持锁访问外部服务。

## Success Criteria

- 授权缺失、错店、跨租户、误用同源不同动作、过期、撤权、伪运行证据和存储中断全部被拒绝。
- 专用 PostgreSQL 上可创建、重新读取两类记录，并验证原队列在单连接池逐条复核且不误认领。
- 保留 `pending_live_validation` 的生产放行门。试点真实店铺、授权和平台运行证据在本轮外。

## 接续范围：受控采证事务

增加仅服务端构造注入的采集器及事务写入契约，不提供客户端提交证据接口。采集器读取当前连接的无密钥投影，在事务外采证；服务校验精确动作、来源、店铺、连接/凭证/同意版本、有效期和契约版本。仓储落库时锁定连接并重新核对版本及撤权/刷新/授权中状态，旧响应不得覆盖新授权。来源映射和动作证据同事务写入，来源不能静默换店。采集失败、错租户、过期、版本漂移均零写入。未配置采集器立即拒绝。生产 proof verifier 缺失时仍不允许外发；新增采证契约不代表真实运行验收。

独立证明验证适配器仅接受构造注入的本地验证源，按产品与 provenance 精确选择，并核对当前提供方契约、精确证明身份、证据模拟标记及有效期。验证源不得在队列锁内访问外部平台。缺失验证源、契约变化、伪证明、过期及来源错配返回空证明。默认生产构造保持不注册，待正式提供方接通后显式装配。

执行凭证接缝由服务端适配器构造已绑定请求及连接身份，参数和全局配置不能赋予绑定。裁决器在实际出站前重查持久授权并比较适配器使用的连接ID、连接/凭证/同意版本及契约；错配、撤权、过期、状态预检失败均零出站。绑定写请求必须经过现有SSRF校验，不跟随重定向，不退回全局密钥；默认执行器未配置适配器时保持原拒绝行为。
