# 浏览器自动化基座总纲（Charter）

> 状态：**总纲 v1（用户拍板，最高优先级约束）**。2026-09-09。
> 本文是浏览器自动化基座一切设计、编码、测试、交付的最高依据；与任何旧文档冲突时以本文为准。

---

## 四条铁律（不可妥协）

### 铁律 1：三平台兼容（抖音 / 小红书 / 闲鱼）

- 基座对三平台**一视同仁**：同一套 UI 编排、同一套原语集、同一套执行引擎、同一套检测协议。
- 平台差异只允许存在于 L3 适配器四件套（Locators / Recipe / Verifier / Signature），基座与 Brain 零平台知识。
- 新平台接入 = 新增一个适配器目录 + init 注册，基座/前端/Brain **零改动**（P5 已验证：R20 半小时内接入两平台）。
- 平台能力差异如实声明（Capability 矩阵），**不吹不实现**：不支持的能力在 UI/API/Brain 三层都会被拒或降级，绝不静默假成功。

### 铁律 2：UI 自动化、模拟人工

- 一切操作走**真实 UI 通道**：寄生在用户自己登录态的 Chrome 里，不用裸自动化浏览器（P1）。
- 写操作必须产生 `isTrusted=true` 的输入（chrome.debugger CDP，P2），事件序列严格对齐 Puppeteer 规范（P3）。
- 执行节奏**模拟人工**：逐字随机延时（对数正态分布）、鼠标轨迹逼近、点击 hold 随机 hold、步间抖动——机器特征最小化（M4 humanize 层）。
- 检测即检测**页面真实状态**：评论区渲染、商品卡出现、拦截页文案，全是用户肉眼可验证的事实，不做接口层伪造。

### 铁律 3：只做基座，大模型驱动，扩展无限

- 基座 = **能力供应方**：原语集（即时原子/洞察/规划式三类）+ 执行引擎 + 检测协议 + 适配器注册表。
- **大模型（Brain）= 唯一的"智能"来源**：目标驱动编排、页面理解、自愈重试，全部由 LLM 在运行时决策；基座不写死任何平台业务流程。
- 可扩展性公式：**新场景 = 新目标语句**（Brain 现场编排），**新平台 = 新适配器目录**，**新原语 = 扩一个枚举三处实现**。三者在基座上正交，组合即"无限可能"。
- 基座对 Brain 暴露的能力清单必须**机器可读**（/platforms API 已落地），Brain 按清单声明能力编排，禁止幻觉调用不存在的原语。

### 铁律 4：全程全自动

- 从"用户输入目标"到"产出可验证结果"**零人工介入**：无人工确认弹窗、无人工补参数、无人工兜底点击。
- 全自动 ≠ 假成功：每一步失败必须**可归因**（ClassifyError 四分类：refresh_token / bad_body / retry / disconnect）+ **可自愈**（LLM 重排/换路）+ **可审计**（browser_command_log append-only 全量落库）。
- 失败的终态也是交付物：会话带着归因结果、截图、命令日志结束，用户事后可查——但不打断执行流。
- 环境异常（Host 掉线/风控页/账号受限）按检测协议自动处置：重试→跳过→标记终止，全程无停顿等待人工。

## 验收标准（每轮迭代对照）

| # | 标准 | 验证方式 |
|---|------|---------|
| A1 | 三平台 UI 编排任务创建/发布/执行/检测全链路可用 | API 真机 E2E，每平台至少一条读链路 completed |
| A2 | Brain 模式在任意已注册平台跑通目标驱动任务 | brain_mode 任务真机执行，LLM 编排步骤全落库 |
| A3 | 模拟人工节奏生效 | CDP 输入带随机延时/轨迹；步间 delay_ms 抖动 |
| A4 | 全流程零人工介入 | 从 create 到 session 终态无任何等待输入的挂起状态 |
| A5 | 失败可归因可审计 | 任意失败 session 的 command_log 能还原每一步命令与错误 |
| A6 | 新平台零基座改动 | 接入演示：仅新增目录+注册，跑通读链路 |

## 本轮（R21）任务

1. Brain 平台知识注入：平台 Locators/Capabilities/DetectBlock 判据注入 LLM prompt，原语清单机器可读喂给 Brain。
2. 检测接线：执行链每步后跑平台 DetectBlock，命中即按 ClassifyError 归因并终止/重试——闭环铁律 4。

4. 三平台真机回归：读链路 API 模式 + Brain 模式各一轮，对照验收标准 A1–A5。
