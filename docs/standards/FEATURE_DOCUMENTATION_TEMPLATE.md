# 功能文档 8 节模板（FEATURE_DOCUMENTATION_TEMPLATE）

> **本文件是模板，不是功能文档本身。** 新建 `docs/marketing-features/<slug>.md` 时复制本文件骨架。
> 校验脚本：[scripts/check-feature-doc.sh](../../scripts/check-feature-doc.sh)（OPT-DOC-13）
> 覆盖率报告：[scripts/feature-doc-coverage-report.sh](../../scripts/feature-doc-coverage-report.sh)（OPT-DOC-14）
> 上游规则：[MASTER_RULES.md](./MASTER_RULES.md)

---

## 为什么有这份模板

功能文档的唯一目的是**回答一个问题：这个功能到底做没做、怎么做的、边界在哪**。

因此本模板强制 §一「功能完成状态」为第一节——**先交代完成度，再讲设计**。这与项目「未完成部分如实标注、不夸大」的文档准则一致；也是本仓库曾出现「声称 100% 完成实为虚假声明」后确立的防线。

| 节 | 标题 | 必填 | 回答的问题 |
|----|------|------|-----------|
| §一 | 功能完成状态 | ✅ 必填 | 做完了吗？哪些是骨架、哪些是规划中？ |
| §二 | 核心原理 | ✅ 必填 | 它凭什么能解决问题？设计依据是什么？ |
| §三 | 设计标准 | ✅ 必填 | 阈值/配额/契约怎么定的？业界对标是谁？ |
| §四 | 架构与模块关系 | ✅ 必填 | 代码在哪？和谁交互？数据怎么流？ |
| §五 | 数据模型 | ✅ 必填 | 落哪些表？关键字段与索引是什么？ |
| §六 | 业务流程 | ✅ 必填 | 一次完整调用/会话经过哪些步骤？ |
| §七 | 前端交互 | ⚠️ 推荐 | 用户在哪里看到它？入口路径是什么？ |
| §八 | 测试策略 | ⚠️ 推荐 | 怎么验证它是对的？覆盖了哪些边界？ |

> §七 / §八 缺失时 `check-feature-doc.sh` 给 **WARN**；`--strict` 模式下 WARN 视为 ERROR。

## 各节写作要求

### §一 功能完成状态（必填）

- 用**表格**逐条列出子能力与状态，状态取值只有三种：`✅ 已完成` / `⚠️ 部分完成` / `🔲 规划中`。
- 必须包含 **已知限制** 段落——没有限制的功能文档视为可疑（任何实现都有边界）。
- 禁止写「基本完成」「接近完成」这类无法验证的措辞。

### §二 核心原理（必填）

- 回答「凭什么有效」，不是复述「做了什么」。
- 有业界依据的（论文、竞品实现、行业标准）**必须标注来源**；纯工程取舍的**必须声明是取舍**。

### §三 设计标准（必填）

- 所有阈值、配额、超时、重试次数以**表格**给出，并写清依据。
- 配置项需标注来源（环境变量名 / `system_config_kv` key / 常量位置）。

### §四 架构与模块关系（必填）

- 指明代码落点（遵循五层架构：Router → Handler → Service → Repository → Model）。
- 画清上下游：谁调用它、它调用谁、跨域边界在哪。

### §五 数据模型（必填）

- 表名、关键字段、索引、**迁移文件编号**（便于按号溯源）。
- 涉及软删除/分区的表要说明策略。

### §六 业务流程（必填）

- 编号步骤，每步写清**输入 → 处理 → 输出**。
- 异常分支（降级、重试、兜底）必须单独成步，不能只写成功路径。

### §七 前端交互（推荐）

- 路由路径、视图文件、API 封装文件三件套齐全才算填。
- 若功能确实无前端入口（如纯后台定时任务），写「无前端入口，触发方式为 <cron/CLI>」并计入已填。

### §八 测试策略（推荐）

- 覆盖点 + 边界用例 + **可复现命令**。
- 有回归测试的要给出测试函数名。

## 校验与报告

```bash
# 结构校验（必填节缺失 → 失败退出）
bash scripts/check-feature-doc.sh

# 严格模式（推荐节缺失也算失败）
bash scripts/check-feature-doc.sh --strict

# 覆盖率报告（含 §四~§八 专项统计）
bash scripts/feature-doc-coverage-report.sh
bash scripts/feature-doc-coverage-report.sh --json
bash scripts/feature-doc-coverage-report.sh --out docs/marketing-features/COVERAGE.md
```

报告脚本的退出码约定：全节覆盖率 < 30% → `exit 1`；< 50% → 警告 `exit 0`；≥ 50% → 通过。
