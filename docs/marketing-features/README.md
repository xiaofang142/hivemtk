## 一、产品是什么

HiveMtk 是一套**开源自部署**的 AI 私域运营系统，解决一个核心问题：

> 商户在微信、抖音、小红书、WhatsApp 等多个平台上有大量客户私信，人工回复跟不上、销冠经验无法复制、跟进动作靠人肉记忆。

系统把这些平台的私信统一接入，由 AI 销售引擎自动识别客户意图、检索知识库、按 SOP 流程跟单；AI 把握不住的对话自动转给人工座席；所有对话效果数据回流用于持续优化。

三个关键设计决策：

- **本地推理优先**：LLM / 向量化 / 重排默认走本机 llama.cpp（Qwen2.5 + BGE-M3），对话数据不出内网；
- **单商户物理隔离**：用户端（本项目）与平台端分开部署，每个商户自己一套；
- **AGPL-3.0 开源**：代码可审计，可二次开发。

## 三、AI 引擎层功能

### 3.1 LLM 调度与降级（F1）

| 能力 | 说明 |
|------|------|
| 场景化路由 | 7 个场景独立路由：意图识别 / SOP 回复 / 异议应对 / 闲聊 / 长摘要 / 高质量生成 / 低成本任务，每个场景可配置不同模型 |
| 四级降级 | 主模型 → 备用小模型 → 语义缓存 → 模板兜底，任一级失败自动落到下一级，业务不中断 |
| 提供商熔断 | 连续失败 ≥5 次熔断 60 秒，延迟 >3000ms 判定降级，多实例间通过 Redis 同步状态 |
| ReAct 适配 | 对不支持函数调用的模型自动注入工具协议提示词 |
| 多数投票 | 关键场景可采样 N=5 取多数结果提升稳定性 |

> 如实说明：多模型投票（MultiModelVote）目前只取质量分最高者的结果，尚未做真正的一致性比对。

### 3.2 Agent 推理闭环（F2）

五阶段流水线：感知 → 对齐打分 → 危机门禁 → 任务规划 → 输出复核。

- 危机关键词三级分类：高危 23 词（退款/骗子/投诉媒体等）直接转人工；中危 14、低危 9 分级处理；愤怒情绪≥0.7 自动升级；
- 单阶段超时 2s、全链路超时 8s，超时快速失败不拖垮响应；
- FAQ 命中可跳过 LLM 直接返回（省算力）。

### 3.3 工具集与护栏（F3）

- **42 个内置工具**：RAG 检索 4 / 客户管理 8 / 订单售后物流 6 / 全渠道触达 20 / 私信与会话卡片 4；
- **12 层装饰器链**：权限→限流→熔断→重试→超时→审计→成本→反馈→死信→结果缓存→双拦截→参数校验，每个工具调用都过一遍；
- **LoopGuard**：同指纹工具调用 60 秒内 3 次即判定循环并拒绝；
- **MCP Server**：零依赖 JSON-RPC 2.0 实现，外部工具可通过标准协议接入。

### 3.4 RAG 检索（F4）

- **四层短路检索**：热缓存（LRU 1024 条/30min）→ 温索引 → 冷索引 → 关键词兜底（权重 0.5）；
- **混合检索**：pgvector 向量召回 topK=50 + BM25 关键词召回 topK=30 → RRF 融合 → Rerank 精排前 20 → 最终取 5；
- 配套：查询改写 / HyDE / 多路改写（后两者默认关闭）/ 增量索引 / 双层缓存。

### 3.5 知识库管线（F5）

- 文档导入（含 URL 抓取，SSRF 校验前置）→ 结构分块 → BGE-M3 向量化（1024 维）→ pgvector 索引；
- 异步处理窗口 15 分钟；向量化服务故障时降级 Hash 兜底保证入库不中断；
- 客户反馈回流：点赞/点踩驱动知识条目优化。

### 3.6 拟人化三层（F11）

1. **文本润色**（<1ms）：去 AI 客套话、去冗余符号、个性化称呼、场景 emoji；
2. **五维评估门禁**：自然度/简洁度/共情度/专业度/说服力加权，阈值 0.85，灰区（0.70–0.85）触发 LLM 重评与重生（上限 3 次），fail_soft 不阻断下发；
3. **行为模拟**（默认关闭）：分条发送、打字节奏、思考停顿，需 A/B 灰度开启。

### 3.7 自学习闭环（F13）

| 子系统 | 干什么 |
|--------|--------|
| FeedbackLearner | 每轮对话效果实时回流 |
| ChampionDialogueAnalyzer | 销冠成单对话向量化聚类，提炼话术入库 |
| PromptIterator | 负样本自动生成 Prompt 改进候选，版本递增可回滚 |
| SOPAutoOptimizer | 5 类结构优化动作：剪枝/合并节点/补异议分支/补共情/调时序 |
| BanditAllocator | Thompson Sampling 自动分配新旧策略流量（探索下限 10%、单臂上限 60%、晋升门槛 100 样本） |
| TraceLearning | 每小时批审 200 条对话，四维评分（相关性/准确性/有用性/安全性），bad 权重×0.85 |

### 3.8 多智能体（F14）

- 三种角色：**sales**（销售转化）/ **cs**（客服答疑）/ **hybrid**（兼顾）；
- 路由优先级：座席挂载 > 渠道绑定 > 默认智能体；
- 工具授权双层把关：注入期按角色过滤 + 执行期二次校验；
- 被动应答模式完整可用；主动外联模式为骨架（见第九节披露）。

### 3.9 质量评测（F15）

- **ChrF 客观轨**：字符级 n-gram 匹配，中文免分词、零成本高频回归；
- **LLM Judge 主观轨**：相关性/准确性/有用性/安全性四维 0–100 打分；
- 支持 EvaluateSingle 单条调试与 EvaluateBatch 批量回归。

## 四、业务流程层功能

### 4.1 入站编排（九步）

一条客户消息进来后的完整链路：

① 查建会话（OneID 合并同一自然人）→ ② 存消息（5 秒去重窗）→ ③ 在线座席直通（人工优先）→ ④ AI 连续回复上限 10 次（防机器人拉扯，超限转人工）→ ⑤ 紧急词直通人工 → ⑥ 智能体选择（挂载 > 渠道绑定 > 默认）→ ⑦ 销售引擎生成回复（12 步管线）→ ⑧ 置信度门槛 ≥0.7 才发送 → ⑨ 落库计数。

### 4.2 销售回复生成管线（12 步）

识别客户 → 回忆记忆 → 意图识别 → 转人工检查 → 匹配 SOP → RAG 召回 → 话术匹配 → Playbook 建议 → 生成候选（ReAct AgentLoop 或直调）→ 行为层 → 润色 → 拟人评估。

- 并行执行受 errgraph 控制（并发≤4）；假流式输出（4 字符/15ms）；FAQ≥0.6 或 SOP 模板≥0.65 走 Layer1 快路径秒答；
- ReAct 循环护栏：最多 5 轮迭代 / 最多 18 个工具 / 总超时 180s / token 预算 50000 / 截断自动翻倍 max_tokens 重试一次。

### 4.3 意图识别（级联）

- 粗粒度 13 类（询价/议价/需求异议/信任异议/竞品/时机/购买意向/售后/流失预警/社交/投诉等）；
- 精细 8 大类 27 子类；规则先行（微秒级），低置信时 LLM 二次确认；
- **投机识别**：规则先出结果先走主流程，LLM 后台异步复判（buffer=1，60 秒收割窗口），升级则追加修正；
- 置信度 ≥0.7 自动挂接 SOP 流程。

### 4.4 SOP 流程引擎

- **19 种节点类型**：起止 2 / 销售话术 9（问候/探需/介绍/异议/促单/邀约/跟进/激活/培育）/ 控制 3（条件/分支/等待）/ 智能 2（LLM 生成/AI 决策下一跳）/ 旧版兼容 3；
- DAG 编排，支持 AB 分流实验；
- 调度器：16 worker / 队列 1000 背压拒绝 / LLM 并发信号量 4 / 任务超时 5 分钟 / 重试 3 次指数退避；
- 幂等保障：`message_sent:{exec_id}:{node_id}` 副作用键防重复发送；
- ⚠️ Saga 补偿机制为空壳（中断续跑能力不完整，见第九节）。

### 4.5 置信度与转人工

- 五信号加权：意图 0.30 / 实体 0.15 / 上下文相关性 0.15 / RAG 0.20 / 熵 0.20；
- 校准链：Temperature Scaling × Platt Scaling → Conformal Predictor（带覆盖率保证的分布无关校准）；
- 六道否决链：显式要求转人工 / 投诉 / 死循环 / 低实体 / 低RAG / 高熵，任一触发强制转人工；
- 动态阈值：基础值 + 客户等级 + 时段 + 座席空闲度调节，区间 [0.40, 0.95]；
- 四档决策：<0.40 转人工 / <0.60 LLM 兜底 / <0.75 人工复核 / ≥0.75 自动发送。

### 4.6 异议处理

七类标准化识别（价格/需求/信任/时机/竞品对比/功能/其他），命中后从话术库取头部话术供生成参考；话术使用次数与转化结果回流，好话术自然上浮。

## 五、渠道触达层功能

### 5.1 渠道接入

权威清单以 [`user-web/src/constants/channel.js`](../../user-web/src/constants/channel.js) 为准（如该文件不存在，以 `user-server` 路由注册 `internal/router/` 中的渠道目录为准）。

| 分组 | 渠道 |
|------|------|
| 即时通讯 | 企业微信、微信公众号、个人微信（聚合）、WhatsApp Cloud API、Telegram Bot |
| 社交平台私信 | 抖音、快手、小红书、闲鱼、TikTok |
| 协作办公 | 飞书、钉钉 |
| 通知触达 | 短信（阿里云/腾讯云/华为云）、邮件（SMTP） |
| Web | 内嵌客服 Widget（embed-sdk，一行脚本接入自有网站） |

被动渠道（Telegram/飞书/钉钉等）Webhook 回调地址通过 `PUBLIC_BASE_URL` 显式声明；留空自动降级 polling 模式（仅适合单实例开发）。

### 5.2 触达能力

- 统一收件箱（跨渠道会话合并）、消息中枢、批量群发、定时任务、消息撤回；
- 平台专属卡片：抖音/快手/TikTok/闲鱼/小红书卡片消息；
- 短链追踪（点击统计）、活码、素材中心。

> 浏览器桥接（Bridge）：通过浏览器扩展在小红书/抖音/TikTok/闲鱼私信页抓取并上报消息，对应 CORS 白名单需包含这四个平台域名。

## 六、客户数据层功能

- **OneID 身份合并**：跨渠道身份归一到同一客户；
- **客户 360**：基础资料 + 全渠道会话时间线 + 订单/售后 + 行为事件；
- **线索管理**：收集、分配、跟进任务、公海；
- **标签与分层**：RFM 模型、行为标签、客群圈选；
- **会话管理**：完整记录、快捷回复、AI 建议；
- **黑名单**：用户级屏蔽。

## 九、已知限制（如实披露）

以下短板在源码审查中确认存在（编号 G1–G12 来自父仓库 [`docs/architecture/AI_CORE_FEATURE_INVENTORY.md`](../../docs/architecture/AI_CORE_FEATURE_INVENTORY.md) 末尾的「已知限制」章节），选购/二开前请知悉：

| # | 限制 | 影响 |
|---|------|------|
| G1 | SOP Saga 补偿空壳 | SOP 执行中途宕机后无法精确续跑，只能整体重跑或人工介入 |
| G2 | MultiModelVote 无真实投票 | 多模型投票名不副实，仅取最高质量分者 |
| G3 | greeting 意图规则不可达 | 问候语意图永远走不到规则分支（常量未入词典） |
| G4 | 置信度两套体系割裂 | 编排层启发式置信度与 confidence 五信号体系未打通 |
| G7 | 行为拟人默认关闭 | 分条发送/打字模拟需手动 A/B 灰度开启 |
| G8 | 异议分类置信度硬编码 0.85 | 分类无真实置信度，首中即返回 |
| G9 | 四层检索短路式 | 可能漏掉冷库中更优结果 |
| G10 | 模板兜底文案单一 | 四级降级最后一级文案无场景区分 |
| G11 | 主动触达未落地 | active 模式仅有骨架，定时主动外联不可用 |
| G12 | 评测较薄 | 无对话级端到端评测集，仅单轮 ChrF + LLM Judge |
