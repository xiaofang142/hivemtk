## 0. 为什么现有做法必须换（三条实证，全部本轮跑/读出来的）

1. **审核规矩住在散文里，散文不是判据。** 与 [[mutation-battery-hygiene]] 同一份文件现在有
   **四十条**口径，本轮我自己仍复现了其中两条被它明令禁止的错：把一格 BROKEN 读数记到**另一份日志
   文件名下**（口径"日志分轮存 / 引用路径要先 stat"），以及第一版注码**打在语法上**（口径"截完整语法块 /
   编译红不是牙"）。读过四十条的人照样犯 ⇒ 缺的不是更多句子，是执行者。
2. **闭合状态靠措辞，于是"还剩几条"没有答案。** 现有表达是 `成立并已修` / `记为已知不补` / `登记不修`。
   本轮为了数清 §八 有几条登记项，我连着错两次：先按"`### 八、登记` 到下一个 `^## `"` 抽出 3 条，
   再"纠正"成 6 条里含 3 条子项——**两次都错**。真实形状是
   **`### 八、登记（看过、本批不做）` 在文中出现两次**（行 1858 属于 §7.24 批20b、行 2129 属于 §7.28 批22），
   每份 3 条顶层项 ⇒ 共 6 条，且两份之间有重叠（`appendCommandLog` 的 `Ignore` 各记一次，
   批20b 的 `comment_verify evidence 无处可查` 已被批22 的 `R_GAP` 腿部分承接）。
   同时用 `^- ` 抽 §6/§2 得 0，因为 §6 是编号列表、§2/§4/§5 是纯段落、§八 是 bullet、
   §8.3 是表格行——**同一份 spec 里承诺有四种形状，同一标题还会按批次重复出现**。
   没有声明式抽取规则时，任何"数几条"都是手抖，包括我这轮的两次。
3. **"不修"不需要代价。** §八 与 §6 里有几条看着更像**功能缺失**而不是取舍
   （`browser_audit_digests` 链完整性的离线重算；裁剪**界变更**的"这个 cutoff 从哪来"没留痕）。
   而"等价类要配自动失效锁"这条规矩只在批16c 用过一次（§7.10），全仓现在只有 3 条这种锁腿
   （`TestSentToFinalLedgerWritePathHasNoEarlyReturn`、`TestBudgetDecoupleWiringLocks`、
   `TestB19FLocalHostBehindForwarderIsNotLockedOut`）。**本协议不预设哪几条该做成真功能**——
   那是 §4 的 A–C 相用注码判出来的；把它写死成本轮要修，等于用另一个"我认为"替掉旧的"我认为"。

## 1. 承诺轴：审什么由"代码对外说过什么"决定

- **承诺**＝ spec 里可指认的一段原文，台账只存指针 `{section, quote}`（`section` 是标题锚，
  `quote` 是该段的前若干字，用于回磁盘核对它真的还在），**不复制正文**，避免两份事实源。
- 每条承诺配一个 **`attack`**：破坏它的最小注码（文件/符号 + 注法）与"哪条腿必须红"的预言。
  审核轴因此不是"再读一遍找感觉"，而是一批可执行的攻击。
- 注码纪律（从本轮两条错长出来，写死在协议里）：必须打在**语义**上（改判据/改条件/改取值），
  不许摘整块致使少掉出口 return 而编译红；红必须读红因；红集合同时有上下界（恰好等于期望）。
- 已知可枚举面（2026-09-22 用同一份解析器数出来，非手感）：§3.x 列表 27 条（bullet 21 + 编号 6）、
  §6 编号 4 条 + 段形 1 项（vue-i18n，全站半径）、**§八 6 条**（两份同名节各 3 条，见 §0.2）、
  §8.3 表格 21 行 ⇒ 列表形共 **58 条**；§2/§4/§5 是纯段落，**不参与计数钉**
  （见 §3 判据 7 的例外声明）。
- 锚点必须含**两级**：所属批次小节（`## 7.24` / `## 7.28`）+ 节标题（`### 八、登记`）。
  只按节标题抽取会把两份同名节并成一份（本轮实测错法），只按行号抽取则一编辑就整体漂移。

## 2. 台账：一条发现只有四种终态

文件 `docs/superpowers/specs/ledger/<round>.jsonl`（一轮一份快照，只追加不重写历史快照），
每行七个字段，`status` 四选一是**穷尽的**——没有"待办"、没有"以后再说"、没有空值：

| 字段 | 含义 |
|---|---|
| `id` | `R22-NN`，稳定不复用 |
| `claim` | `{section, quote}`，指向承诺原文；`quote` 有 12–96 字两道界——下界防止短到在同一节里撞车（等于没点名是哪条），上界防止抄成正本（两份事实源）|
| `attack` | 破坏该承诺的最小注码（含"注在哪、怎么注"） |
| `status` | `fixed` \| `refuted` \| `locked-equivalence` \| `blocked` |
| `evidence` | 形状随 status 而定，见下 |
| `next` | 可执行的下一步（`blocked` 必填，其余可空） |
| `first_seen` | 发现日期（门用它核证据的时间顺序） |

各 status 的 `evidence` 必填形状：

- `fixed`：`legs[]`，每项是 `{pkg, name}` —— 名字必须能在**它所属的那个包**里被
  `go test -list '^<name>$' <pkg>` 点到（缺 `pkg` 时门无从定点，早先一版只写"腿名"就是这个洞），
  外加 `logs[]`：**持久化证据路径**（本轮定为 `docs/superpowers/specs/ledger/logs/<round>/…`，随仓走），
  文件必须存在且 `mtime ≥ first_seen`。**`/tmp/**` 一律不许作证据**——本轮已经实测过一次：
  `--keep` 留下的私有克隆 `b20b_full2` 在写下引用
  三分钟后就不在了。若某条读数只在临时目录里跑出来过，它不算证据；要么把日志 `cp` 进上面那个持久目录，
  要么改填 `repro`（一条可重跑的完整命令 + 期望的判定行原文），由重跑代替旧日志。
- `refuted`：`reverify` —— 一句"刀是怎么注的、看到什么读数"。出现"我认为/应该/大概"这类无动作词判红
  （规矩来源：§7.10 判定口径"把那把刀真注进代码、看有没有腿红，不看报告怎么说、也不看我怎么说"）。
- `locked-equivalence`：`lock_leg` —— 必须 grep 到同名 Test 函数，且该锁腿自己配了一条**行为不变**的注码
  证明它有牙（会改行为的注码证不了静态锁）。
- `blocked`：`owner` + `due` + `next`。**`due` 一过，门判红**：过期阻塞就是遗留，不能靠"它是别人的事"存活。

## 3. 闭合门：`scripts/check-review-closeout.py`

九条判据，任一不满足 `rc≠0`：

1. `status` 缺失或不在四终态集合内。
2. `fixed` 的每条腿**按其形状**点得到，两种形状之一：
   - Go 腿 `{pkg, name}`：单独 `go test -list '^<name>$' <pkg>`（只编译不跑，约 5s/包）命中；
     `pkg` 缺失、该包里点不到、只有 `pkg` 没有 `name`、`name` 写成正则 ⇒ 红。
     用例名允许中文（`^[^\W\d]\w*$`——本仓实测有 `TestIsDuplicateReason_只认重复结论短语不认任意子串`
     这样的腿名，早先那版只认 ASCII 的形状把**真腿**判成了假红，比漏红更糟）。
   - 脚本腿 `{script, invocation, expect}`：守卫脚本在仓内存在、`invocation` 里逐字出现该脚本路径、
     `expect` 写清"判定看哪一行"（≥12 字）。加这一族的理由：§8.3 里有四条承诺的腿是 vitest/脚本
     （如 SentCache TTL 的 `test/downlink-b20d-sentcache-ttl.test.js`），只有 Go 腿形状时它们
     只能被记成"没有腿"，于是"无牙"和"有牙但门看不见"在台账里长得一模一样。
3. `fixed` 的每条证据路径存在、`mtime ≥ first_seen`，**且不在 `/tmp/**` 下**（不在仓里的东西不叫证据）；
   若该条改填 `repro`，则必须同时给出期望判定行原文，`repro` 不计入日志侧、由 C 相实跑填充。
   日志项还可以写成 `{path, must_say, must_not_say}`：门打开那份文件、逐条核断言串是否真在里面。
   加这一支的理由是实测到的一种失效形状——**文件在、也新，内容却是另一趟跑的读数**：局部调试跑
   （`--only` 子集）与全量跑写同一个取证文件名，后者被前者原地覆盖，闭合门的存在性检查照绿，
   而它核的那份证据已不再证明它承诺的那件事。只写 `path` 的字典项等于退回存在性检查，判红。
4. `refuted` 的 `reverify` 非空且含动作词（注码/复跑/红因/还原 之一族）。
5. `locked-equivalence` 的 `lock_leg` 函数名存在。
6. `blocked` 的 `owner`/`due`/`next` 三者齐备，且 `due` 未过期。
7. **source-map 计数钉**：台账头部声明每条抽取规则，键是 **(所属批次小节, 节标题, 形状)** 三元组，
   并钉其**期望条目数**；实抽数 ≠ 钉值 ⇒ 红。散文长出新承诺时，门逼着要么补台账行、要么显式改钉值并写理由。
   不参与计数的节（§2/§4/§5 段形）必须在 source-map 里显式声明为 `prose-not-counted`，
   否则视为漏声明。键里带批次小节不是冗余：`### 八、登记` 实测有两份，只按标题抽就会并成一份（§0.2）。
8. **claim 指针可追**：`claim.section` 必须点得到 spec 里真实存在的一节，`claim.quote` 必须是该节
   某一条目里的**连续原文**（不许改写、不许跨两条拼、不许留空）。这一族管的是"台账指向的承诺还在不在"——
   计数钉只保证条数，不保证每条仍指着原文。
   并且 `claim.section` **命中两份同名节即判歧义红**：条目抽取把两份同名节的条目并成一个池子，
   所以 A 节的原文会在 B 节名下"匹配成功"，而对账按 `##` 节统计条目数 ⇒ B 节的钉永远 0 条、
   A 节白捡若干条。本型实测错过一次（`### 八、登记（看过、本批不做）` 在 §7.24 与 §7.28 各一份，
   第一版台账把 §7.24 的三条切给了 §7.28 的钉，quote 侧全绿）。修法：这类条目改填所属 `##` 批次节标题。
9. **coverage 归属声明**：spec 里**每一个 `##` 节**都要在 `meta.coverage` 里出现一次，声明它的归属：
   `ledger`（进闭合面，`total` = 该节自有序段里可数承诺的实测条数，抄 `--dump` 的那一列）或
   `out-of-scope`（带 reason，说明为什么这一节的承诺不由本台账收口）。
   未声明的节＝盲区：那一节里新长出的承诺没有任何东西会红。实测读数从"21 节 / 292 条可数承诺、
   门只看得见其中 31 条"变成"21 节全部有归属，4 节进台账、17 节写明 why not"。
   聚合计数走 `own_segments()`（把每个 `##` 块按子节标题切段，只数标题自己名下的那段）——
   直接数整块会把"父节 + 其子节"重复计入：父节名下的可数条目已被子节各算一次。
   并且**声明为 `ledger` 的节必须有已验的计数钉**：`coverage` 与 `scope` 是两个字段，只写
   "这节进闭合面"却不钉它的条数，`reconcile()` 根本不看这一节 ⇒ 抽轴可以整体不做而门全绿
   （2026-09-23 加这条判据时，自检里立刻有 8 格因它混红——那 6 格是"钉被摘掉当隔离手段"的格，
   另 2 格是钉自己坏掉的格，同因两条红收进 WANT 的允许项）。

门的性质：只读文本 + `go test -list`，不连库、不跑用例 ⇒ 可与并行 lane 同树共存；
仍按本仓惯例在私有 `--shared` 克隆里复跑一次以证自洽（`check-env-coverage.py` 那一条口径）。

**门自己必须有反向测试**（新校验不反向测＝没有校验）：`--selftest` 现造 **59 种**坏条目
（收口轮末次实测读数 `59/59 隔离 + 合法快照 0 红 rc=0`；第一版是 13 种，本轮补上 46 种），
按判据族分：条目形状与身份（缺/非法 `status`、缺 `id`、`id` 重复）、**腿**（Go 腿名点不到 /
腿所在包跑不出名单（红因写成"这棵树的编译状态"，与"腿不存在"分开——并行的未跟踪文件把包连着撞断两次，
台账一字未动却红两条）/ 腿名写成正则 / `pkg` 越界 / 带 `pkg` 无 `name` / 守卫脚本不存在 / `invocation` 指不到脚本 /
脚本腿 `expect` 太短）、**证据**（不存在 / mtime 早于 `first_seen` / `first_seen` 在未来 /
落在 `/tmp/**` / 用 `..` 逃逸 / 空串 / 缺 `first_seen` / **内容断言没命中** / 出现不许出现的串 /
字典项缺 `path` / 字典项只写 `path` 不给断言 / `must_say` 非数组 / `logs` 项是数字 /
**禁串只在尾部**（读窗只覆盖头部时限定的"不许出现"永远读不到 ⇒ 门假绿）/
**禁串被 ANSI 遮挡**（断言按人眼在那份日志里读到的那句话写，判读前先脱色））、**承诺内容**（`attack` 缺失或只有形状）、
**repro 形状**（自由文本 / 缺 `expect`）、**meta 与 source-map**（spec 绝对路径 / spec 指不到文件 /
无 `scope` / 空台账 / 钉的节名点不到 / 计数钉不符 / 钉已验但没抽轴 / `prose` 豁免无 reason）、
**等价类锁腿**（无锁腿 / 锁腿点不到）、**blocked**（已过期 / 缺 `next` / 缺 `owner`·`due`）、
**refuted**（`reverify` 无动作词 / 空）、**claim 指针**（`quote` 非原文 / 跨条拼接 / 为空 /
`section` 点不到节 / `section` 命中两份同名节 / `quote` 抄整段正文（>96 字上界）/
`quote` 只有 4 字（<12 字下界——短到在同一节里必然撞车，等于没点名是哪条承诺））、
**coverage 归属声明**（节未声明归属 / 声明的总数不符 / 声明不存在的节 /
归属状态非法 / 重复声明同一节 / 声明 `ledger` 却没有已验的计数钉）
⇒ **59 种全红**；另附一份合法台账快照 ⇒ **0 红**。缺任一侧都不算这门有牙。
后两族是本轮长出来的：前者把「审计面只数非空 `legs`」这个盲区收掉（脚本腿＝非 Go 交付的
唯一可点形状，否则 §8.3 里那些 vitest 腿只能被记成"没有腿"），后者把「整节没进任何键」
从"门不管"变成"门必红"。收口轮又往**证据**那一族接了 8 格：前 6 格管 `logs[]` 的形状与内容
（字典项要门打开那份文件逐条核 `must_say` / `must_not_say`），后 2 格管**门自己读得到多少**——
`log_window` 只回头部时，"禁串只在尾部"永远读不到；断言写给带颜色的终端时，ANSI 转义会把
被钉的那句话切碎。两格各配一个合法快照正例（`ST-WINDOW` 钉只在尾巴上的读数、`ST-ANSI` 钉
被色码包住的串），否则"改宽窗口/先脱色"这种修法本身没人测。内容断言族管的形状不是"证据不存在"，而是"证据在、mtime 也新，
内容却是另一趟跑的读数"——那种文件只核存在性的门会一直绿着（主 spec §九·五记了实撞到的那一次）。

红还不够——每种坏条目要**红在自己那一条判据上，且不混进别格的红**：自检有一张 `WANT` 表，
每格第一项是该判据的签名关键字（必须出现），其余是"这一格本来就一次报全"的允许项
（等价类同时缺 `lock_leg` 与 `lock_attack`；节名点不到的钉会连带计数不符）。
这一条是本轮跑出来的：第一版只要求"报错文本里出现关键字"，13 格里 7、11 两格各带 2 条红，
读一遍才发现"红"和"这一格有牙"是两件事。判据本身也要摘掉验：把 `check_claim` 换成 `pass`
⇒ 第 12、13 格立刻"没红"（`11/13`），装回去 ⇒ `13/13`，还原后 md5 与摘除前一致。

- **这条纪律不只管闭合门，管本轮每份带 `--selftest` 的门禁件**：`merge-gate.py --selftest`（16 格：
  `--only` 打错步名要拦停、`DIAG` 豁免只绿诊断步不许绿普通门、被调脚本改名/删掉要红成"这一步等于没跑"、
  **子集跑不许写全量取证名**——收口轮新加的那一格管的正是"`--only` 调试把台账引用的全量证据
  原地覆盖"这个形状）、
  `run-gate-in-clone.py --selftest`（11 格：克隆侧汇总为空不算一致、工作树有汇总而克隆侧空要红、
  泳道叠加名单逐字对账，收口轮再加两格管"判决行要进脚本自己写的那份取证"，绿侧红侧各一格）、
  `run-gate-family-selftests.py --selftest`（4 格：成员零输出要红、成员退非 0 要红、好读数不误伤且

## 4. 执行流程（A–E 五相）

- **A 抽轴（我）**：按 §1 的承诺来源逐条写 `{claim, attack}`。这一相禁止出现"应该已经覆盖了"。
- **B 找反例（子代理 × N，无上下文）**：一轴一路，**明令不许读台账、§七证据与我的结论**，
  只回答"哪条注码破坏了这条承诺而全套仍绿"。理由：§7.9/§7.10 那轮的外部轴命中了 6 处当时真洞，
  而同上下文自审会复现"我看到过所以以为对"。
- **C 逐条复验（我）**：每刀真注进私有克隆、跑、读红因，落进四终态之一。**禁止按报告原文入库**
  （[[verify-secondhand-review-claims]]），报告若错也要留下否决理由。
- **D 修 + 回归**：补腿、改判据、单包回归；**串行**执行，先探测并行 lane（`pgrep -fl "go test"`、
  `load`、目标文件 mtime），不与别人的电池/门禁并发跑同一棵共享树，电池一律私有 `--shared` 克隆。
- **E 收口**：一次合并门禁（全量，**不带 `-run`**）+ 闭合门 + `--selftest`；报告末行照例写"本轮没跑的"。
  - 收本轮自身时必须按此序跑，否则"引用那趟跑出来的日志"的条目永远凑不齐（先有鸡还是先有蛋）：
    ① 先生成台账（`scripts/build-review-ledger.py <round> --bootstrap`——它把"证据还在盘上等下一趟"
    的那几条记成待补而非停机）；② 跑闭合门，读数**应为红**（缺证据），这份红原文留作判据 3 的反向取证；
    ③ 跑合并门禁（驱动器**逐行流式**写自己的摘要，所以它一开工证据文件就在，末尾的 rc 才是真读数）；
    ④ 复跑闭合门到绿。台账的 `first_seen` 与日志 mtime 的比较（判据 3）因此天然成立，
    而"绿读数指向自己那趟"这件事要在报告里写明，不能当成独立复核。
  - **判定分母只放"树内可判定"的门步。** 本轮实测撞出来的形状：`check-ci-step-coverage.py` 自述
    「人工核查用的诊断脚本，故意不挂进 CI——挂成门就是永远红，等于亲手再造一个常亮红灯掩盖下游」，
    而我把它排进了合并门禁 ⇒ 它红在"CI 历史里 user-web ESLint 从未通过（HEAD `1bce38c3` 报 2 errors）"，
    而**工作树**同一条命令 0 errors（那两处正是本泳道未提交的改动）。历史读数不是本轮的代价，
    所以这类步归入 `merge-gate.py` 的 `DIAG`：照常跑、照常落全量日志、照常印红因，只是不改判定；
    豁免表自身要有牙（名字不在步骤名单就停机 + `--selftest` 三格），**且它查出来的真缺陷必须换成
    一道树内门**（本轮补的 `lint-bridge` / `lint-user-web`）——只挪档位不补腿，等于把门改成告示牌。

## 5. 越界改动纪律（本轮范围＝全仓归零，含别人的红）

- 只允许**单行、最小精确匹配**的改动（`Edit` 精确串），禁止"整文件快照写回"（那会抹掉对方在飞的编辑）。
- 改前读一次、改后立即复读并核 md5；mtime < 60min 的文件视为在飞，先 `diff` 留快照再动。
- 每处越界改动产出一条"我动了你哪一行"清单，随本轮报告交给并行 lane。
- 不为凑绿而改别人的**期望或判据**（同"改期望不改变异"）。
