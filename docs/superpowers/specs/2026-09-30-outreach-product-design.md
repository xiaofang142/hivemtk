# hivemtk 自动触达产品设计（browser-automation × JEV）

- 日期：2026-09-30 ｜ 状态：已确认 ｜ 前置：JEV v1.1 统一调度（`docs/browser-automation/jev_integration_design_step4.md` §7）

## 1. 产品定义

为 hivemtk 本体服务的**社交平台自动化触达**：批量、拟人、可审计地完成留言 / 评论 / 私信。
北极星指标：**触达成功率、账号存活率、单次触达成本**（不是"任务跑通"）。

## 2. 五维设计（每维：现状 → 论证 → 产品需求）

### 2.1 JEV 模型配置：按平台难度分级
- 现状：env 四件套 + 默认关闭；v1.1 走 dispatcher `ScenarioJevChoice`。
- 论证：批量触达对成本极敏感，统一强模型=烧钱；熔断 off 后直走更贵的 Brain，成本方向反了。
- 需求：三层配置（平台默认→租户/用户覆盖→任务级覆盖）+「平台→模型」分级映射表 + 降级链（先降 JEV 模型，再谈 Brain/人工）+ 灰度切流。

### 2.2 通用任务设计：触达任务模型（核心）
- 任务 = 目标（用户/帖子列表）× 动作（评论/私信/关注/点赞）× 文案策略 × 频次。
- 论证：v1 无 TYPE_TEXT ⇒ 触达场景 JEV 覆盖率为 0，回退率会吞掉全部收益。
- 需求：① TYPE_TEXT 最高优；② 文案一等公民（LLM 生成＋敏感词过滤＋人工抽审，D7 闸门卡点位）；③ 用户级触达去重键（推广写台账 `text_hash/is_write` 思想）；④ 两层规划（task planner 拆步/断点续跑 ＋ JEV 单步 choice）。

### 2.3 LLM 调度：双重限频下的批量并发
- 论证：平台侧限频（防封）＋模型侧限频（成本）同时存在，dispatcher 只懂后者。
- 需求：活动级预算（单次触达成本核算）＋账号轮换队列＋任务时间线可观测（每步：模型/token/延迟）＋任务级并发优先级。

### 2.4 基座感知：社交站特化
- 现状：@eN 快照（250 上限）＋整页指纹防 stale ＋ CDP trusted。
- 论证：信息流虚拟滚动撞上限；@eN 漂移时五项校验变误杀器；掉线只表现为"任务卡住"。
- 需求：滚动分页感知、元素级新鲜度（点前复核包围盒）、关键步截图＋VLM 复核、多账号 cookie 池（掉线换号不中断活动）、弹窗/滑块标准处理链、用户可见的浏览器/账号状态。

### 2.5 全链路：触达旅程闭环
活动创建（目标＋文案＋频次＋账号）→ 执行（频次控制、**封号熔断**：账号异常立即停该账号任务并告警）→ 验收（**触达回执**：截图＋帖子链接留存）→ 复盘（成功率/封号率/回复率看板）＋用户账单（JEV 独立口径已具备）。

## 3. P0 路线（触达视角）
1. TYPE_TEXT（JEV action 空间补齐）
2. 账号池 ＋ 封号熔断
3. 用户级触达去重
4. 活动级预算 ＋ 任务时间线可观测
5. 触达回执留存

## 4. 非目标
- 通用全网 RPA、验证码强对抗（先标准处理链＋转人工）、开放平台 API 化（后置 P）。
