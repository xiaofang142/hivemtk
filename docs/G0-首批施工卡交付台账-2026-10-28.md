## D06｜修正流失金额与事件契约

- **修复 1（主缺陷，findings.md 点名）**：`ops/service/churn_prediction.go` 的 `aggregateCustomerBehavior` 曾把 `PurchaseCount90d`（购买次数）赋给 `AverageOrderValue`。现在金额从购买事件 payload 的 `amount` 真实解析（Go 侧 JSON 解析），`AOV = 净额和 / 有效订单数`；`order_id` 重复事件只记一次；缺金额/坏 JSON/负数不计入；多币种混加判 unknown（不直接加）。
- **修复 2（连带潜伏缺陷，本轮新发现）**：SQL 别名 `purchase_count_90d`/`interactions_30d` 与 GORM 对字段名的映射 `purchase_count90d`/`interactions30d` 失配（数字前不加下划线），生产聚合里频次与互动数**一直静默扫成 0**。别名已改为与 GORM 映射一致。
- **修复 3**：金额 unknown（无凭据/混币种）时不再把 0 当真值喂给评分：`CalculateChurnPrediction` 支持 `average_order_value_known=false`，排除客单价分量、其余权重按比例重归一；"订单金额偏低"因子不再凭缺数据产生。泛化 map 入参未带标志时保持旧行为（历史调用方零变更）。
- **测试**：`internal/ops/service/churn_prediction_aov_test.go` 9 个用例（含验收基准：订单 100+900 → 频次 2、AOV 500；去重；坏 JSON；混币种；重归一数值；旧路径回归；端到端）。`go test ./internal/ops/service/` 全绿（41.4s）。

## D03｜AI 延迟队列 sending 悬挂处理

- **模型**：`reach_delayed_outbound` 增加 `ClaimToken/ClaimedAt/LeaseUntil`（AutoMigrate 自动加列）与 `unknown` 状态。
- **仓储**：`PickDueForUpdate` 逐行签发 token+5 分钟租约；`MarkSent/ScheduleRetry/FinishReplay` 全部带 token 栅栏（旧 worker 回写 0 行拒绝）；新增 `ClaimSendingRows`（fallback 路径）、`ListExpiredLeaseSending`、`ListLegacyStuckSending`、`MarkSendingUnknown`、`ResolveUnknown`（pending/sent/superseded 三出口）。
- **服务**：`recoverStuckDelayedOutbound` 在每轮派发后执行：legacy 无租约悬挂行 → unknown（不自动重发）；租约过期行 → 会话已被回复则自动 superseded（安全终态），否则 unknown 待人工核对。替代原"只观测不回收"。
- **测试**：`delayed_outbound_lease_test.go`（栅栏拒绝/改排清租约/回收转 unknown/核对收敛）+ `webhook_outbound_lease_recover_test.go`（服务层四行齐测）。repository 包全量 496s 全绿；webhook 系测试全绿。
- **测试基建备注**：GORM `First(&dest, id)` 会把 dest 已有主键并进 WHERE（`id=? AND id=?`）——复用 dest 变量必然 not found；新测试统一用 `readReply` 全新 dest。

## D02｜主动触达 quiet 队列持久化

- **模型**：新表 `reach_deferred_outbound`（完整 ReachSendRequest JSON 快照 + purpose + send_at + 租约三件套）。
- **仓储**：`reach_deferred_outbound_repo.go`——入队/认领（SKIP LOCKED+token）/sent/retry/failed/reschedule/unknown/resolve/管理查询/取消。
- **服务**：`PersistentQuietHoursQueue` 实现 `SendQuietHoursDeferrer`；worker 重发经**原管线**且 ctx 带 quiet-bypass 标记（重发不再二次判延，防自旋）；失败退避改排（1 分钟起步、静默窗口顺延），3 次判 failed；租约过期转 unknown 不自动重发。job id 回填 `req.Metadata["deferred_job_id"]`。
- **装配**：`app/reach_tool_wiring.go` 生产路径（db 非 nil）用持久队列，旧内存队列仅剩测试/降级路径。
- **管理口**：`GET /api/reach/deferred-outbound`（列表）+ `POST /api/reach/deferred-outbound/:id/cancel`（仅 pending 可取消）。
- **测试**：`reach_deferred_quiet_queue_test.go` 6 用例——重启后仍有一条待发、按原意图重发+ctx 带 bypass、失败有持久结果与重试计划、取消不发送、租约过期 unknown、再判延改期同一行不重复。全绿。

## D04｜可信同意与故障拒发

- **新域（五层）**：`contact_consent_events`（追加式授权/撤回事实账，最新事实=当前状态，永不 UPDATE 历史）+ `contact_preferences`（渠道/目的暂停快照，唯一键含 tenant）；仓储/服务/控制器/路由齐备。
- **管线 consent 闸**（独立于 DNC 配置）：撤回即生效——**metadata 伪造 `consent=true` 压不过真实撤回事实**；paused 按持久延后（复用延迟队列，恢复时刻明确则延到该点）；missing 按 `ConsentMode` 处理：`revocation_only`（默认，存量放行但 step log 标 `consent_legacy_assertion`，不批量伪造历史同意）/ `enforce`（拒发）。延迟队列重发走同一管线 → **排队后撤回不发送**。
- **DNC fail-closed**：`DoNotContactService.IsBlockedStrict` 故障上抛；管线优先走 strict，DB 故障拒发并留原因码 `dnc_unavailable_fail_closed`。被动客服等旧路径保持 lenient 不动。
- **管理口**：`GET/POST /api/contacts/:customer_id/consents`（时间线/追加事实）、`GET/PUT /api/contacts/:customer_id/preferences`。写操作 actor 取登录上下文 `user_id`，不接受请求体自报。
- **测试**：`contact_consent_test.go` 6 组——状态机（grant/revoke/渠道范围/后写赢）、偏好暂停（渠道行优先/到期恢复）、撤回压过伪造 metadata、排队后撤回重发被拦、revocation_only 留痕+enforce 拒发、DNC 故障 fail-closed。全绿。

## D05｜配额原子预占与幂等扣额

- **模型**：`reach_quota_counters`（scope×日 已用额度，行锁真源）+ `reach_quota_reservations`（意图预占，intent 唯一，token 栅栏）。
- **语义**（全部 CAS 落地）：预占单事务（锁 counter → 判上限 → used+1 → 落预占行），外部调用绝不持锁；同 intent 同 payload 重入=复用（失败重试不重复占额）；同 intent 异 payload=`ErrQuotaIntentConflict`；commit 幂等（重复回执不重复计数）；unknown 不释放（可事后核对 commit）；release 仅限确定未发送，committed/unknown 拒绝（取消已提交动作不错误返额）；伪令牌拒绝。
- **管线结算**：仅当调用方带 `action_intent_id` 幂等键才预占（无键不占，零行为变更）；成功/Deferred→commit 保留；可重试失败→保持 reserved（重试复用同预占）；不可重试失败→release 返额；分类不出→MarkUnknown。
- **装配**：scope=每客户每日，上限走参数中心 `reach/global_per_user_daily_limit`（默认 0=不设额）。Redis 不参与硬额度（QPS 层既有实现不变），Redis 不可用不退化无限放行。
- **测试**：`reach_quota_test.go` 7 组（含 30 并发抢 limit=5 的原子性验证：used 恰好 ≤5 且 granted==used）。全绿。
