# HiveMtk 用户端 - 部署架构（用户端视角）

> 用户端独立部署（私域模式）
> 本文档聚焦**用户端**部署：客户本地运行的部分

---

## 一、定位与边界

HiveMtk 系统按 **数据主权** 拆分为两端：

| 端 | 所有者 | 运行位置 | 数据 |
|----|-------|----------|------|
| **平台端（Platform）** | 运营方 | 云服务器 | License / 版本 / 元数据 |
| **用户端（User）** | 企业客户 | 客户本地 | 访客对话 / 知识库 / RAG |

**唯一跨域弱依赖**：用户端 `user-server` 经 `PLATFORM_API_URL` 向平台端 `platform-server` 做**低频 HTTPS** 许可/产品同步（几秒一次心跳，**非对话流量**）。

## 三、组件清单

| 组件 | 端 | 运行位置 | 推理栈 | 发布方式 |
|------|----|----------|--------|----------|
| `user-server` | 用户端 | 本地 | 调用本地推理 | 纯 git 提交推送（开源版无 OTA） |
| `user-web` | 用户端 | 本地 / 云端托管回退 | 无 | 纯 git 提交推送（开源版无 OTA） |
| `embed-sdk` | 用户端 | 随 user-web 部署 | 无 | 随 user-web 一起发布 |
| `llama-server :8207` | 用户端 | 本地（宿主机进程） | 是 | `scripts/inference-host/` |
| `llama-server :8208` | 用户端 | 本地（宿主机进程） | 是 | `scripts/inference-host/` |
| `llama-server :8209` | 用户端 | 本地（宿主机进程） | 是 | `scripts/inference-host/` |
| `PostgreSQL user_db` | 用户端 | 本地 | - | 命名卷持久化 |
| `Redis` | 用户端 | 本地 | - | 命名卷持久化 |

## 四、通信矩阵

| 调用方 | 被调方 | 协议 | 是否出域 | 说明 |
|--------|--------|------|----------|------|
| 访客浏览器 | user-server | WSS/HTTPS | 经公网 | 网页客服浮标（FRP / 公网）|
| 客户员工 | user-web → user-server | HTTPS | 经公网（云端托管时）| 页面在云，API 回本地 |
| 客户员工 | user-web（本地自托管）→ user-server | HTTP | 不出域 | 完全内网 |
| user-server | platform-server | HTTPS | 出域（低频）| 仅许可/产品同步心跳 |
| user-server | 宿主机 llama-server (:8207/:8208/:8209) | HTTP | 不出域 | RAG 检索/生成 |

## 五、dev / prod 模型档

| 档位 | LLM | Embedding | Rerank | 用途 |
|------|-----|-----------|--------|------|
| **dev（轻量，当前默认）** | Qwen2.5-3B-Instruct (Q4_K_M) | bge-m3 (1024 维，Q4_K_M) | bge-reranker-v2-m3 (Q4_K_M) | 本机/小内存部署 |
| **prod（重量）** | Qwen2.5-14B-Instruct (Q4+) | bge-m3 (1024 维) | bge-reranker-v2-m3 | 生产质量 |

> 以上模型定义见 `.env-example` 中的 `LLM_REPO/LLM_FILE` / `EMBEDDING_REPO/EMBEDDING_FILE` / `RERANK_REPO/RERANK_FILE`（统一管调参，不直接改脚本）。

切换档位：

```bash
# dev 档（默认）
make inference-host-models         # 下载 dev 档三模型
make inference-host-up             # 启动三服务

# prod 档（16G+ 内存机器）
make inference-host-models-prod    # 下载 prod 档三模型
HIVEMTK_PROFILE=prod make inference-host-up
```

> **铁律**：embedding 维度硬性 **1024**（bge-m3 输出维度）；严禁运行时降维（pgvector 列已锁定）。`EMBEDDING_ALLOW_FALLBACK` 仅测试可开，**生产严禁**（统一在 `.env-example` 中标注）。

## 六、端口一览（用户端）

| 服务 | 端口 | 说明 |
|------|------|------|
| PG-user | 8202 | 用户端库 |
| Redis | 8203 | 用户端缓存 |
| user-server | 8204 | 对话核心 API + HTTP 长轮询 |
| llama-server (LLM) | 8207 | llama.cpp 推理 |
| llama-server (Embedding) | 8208 | llama.cpp 向量化 |
| llama-server (Rerank) | 8209 | llama.cpp 重排 |

> 平台端端口（8201/8205/8211/8213）不在用户端部署。
> 前端（user-web / embed-sdk）在宿主机构建，dist 由 user-server 静态托管，无独立前端容器。

## 七、容器启动顺序（关键）

> 重构后（2026-08-17）：本项目**不再容器化** user-server / 推理栈 / 前端，**仅数据层（PG + Redis）走 Docker**。本节保留 Docker 时代的语义提示，**新版请改用 Makefile**：

```bash
# 1. 启动推理栈（宿主机进程，由 scripts/inference-host/start-all.sh 拉起）
make inference-host-install   # 首次安装 llama.cpp 二进制
make inference-host-up        # 启动 LLM / Embedding / Rerank 三个宿主机进程

# 2. 启动 user-server（宿主机进程，由 Makefile + air 拉起）
make user-build               # 编译二进制（生产）
# 或
make dev                      # air 热更新（开发）

# 3. 数据层由 Docker 提供
make db-up                    # docker compose up -d 拉起 mtk-postgres + mtk-redis

# 4. 验证
curl http://127.0.0.1:8204/healthz
```

**禁止反过来启动**：user-server 依赖宿主机 llama-server 提供 Embedding/Rerank/LLM 推理能力，先起 user-server 会导致 RAG 不可用。

> 旧版 Docker 启动顺序（`make inference-up` / `make user-up` / `mtk-inference-net`）已废弃——这些 target 与网络在 2026-08-17 重构中删除，请改用上方的 Makefile + `scripts/inference-host/*` 宿主机脚本。

## 八、公网可达方案

### 方案 A：有公网 IP / 已备案域名

直接在云服务器上：

```bash
# 把 8204 暴露到公网（注意 HTTPS！）
# HTTPS 终结由外部 CDN / 反代负责（如有需要可自行配置）
```

### 方案 B：无公网 IP（NAT 内网）

使用 **FRP 穿透**：

1. 在轻量云部署 `frps`（配置见 `docs/architecture/FRP私域部署指南.md`）
2. 本地机部署 `frpc`，把 `user-server:8204` 映射到 `chat.你的域名.com`
3. 客户官网集成：
   ```html
   <script src="https://chat.你的域名.com/embed/marketing-chat-widget.iife.js"></script>
   ```

> FRP 二进制需自行下载（推荐 v0.70.0+），可放入 `offline-deploy/frp/bin/`（首次部署时手动建立目录）。脚本化下载可使用社区提供的 `download-frp.sh`（仓库内暂无自带脚本，需自行准备）。

## 九、风险与边界

- **数据主权**：对话与 RAG 全留本地，平台端只碰许可/产品元数据。
- **FRP 单点**：`chat.你的域名.com` 依赖 frpc 在线；frpc 掉线 → 网页客服不可用，但本地对话不丢。
- **版本离散**：用户端开源无强制升级，各客户版本可能不一致，需记录各客户版本以便支持。
- **CORS**：用户端 API 默认放行 `CORS_ALLOW_ORIGINS_USER` 中配置的域名。
