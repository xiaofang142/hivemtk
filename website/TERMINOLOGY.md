## 四、术语检查命令

```bash
# 在 website/ 目录内执行：这是**评审辅助**，不是零命中硬门
cd website
grep -rn "用户端\|商家端\|客户端\|激活码\|免费注册\|一键部署\|授权码\|注册开户\|联系开通\|版本下载\|离线包\|安装包\|无 License\|无授权\|AI 私域销冠\|营销智能体套件\|获取商户标识\|前往下载" src/
```

命中后要逐条读上下文，**当前存量命中分三类**（实测 2026-09-21：`用户端` 33、`客户端` 6、`一键部署` 11、
`授权码` 8、`版本下载` 9、`离线包` 1、`安装包` 1、`无授权` 8）：

1. **属于规范词，不算违规**：`用户端`（与 `user-server` / `user-web` 对齐，见下表注）；
   `无授权码` / `无版本下载` / `无离线包` 这类**否定式**——产品确实没有这些环节，是应当宣传的事实。
   本仓另有零命中硬门 `scripts/check-no-xapptool.sh`（旧域名回流），那才是"必须为空"。
2. **译文里的词面命中**：`客户端` 多数来自 `PostgreSQL（客户端）` 一类技术名词的 4 语言译文，不是"商家客户端"。
3. **存量文案债，改文案时要一并收口**：`一键部署`（`content.js` 的 FAQ 与部署副标题在用，
   与 §二「禁止一键部署」冲突）。它不在任何 CI 步骤里，所以不会自己变绿——
   触碰这几条 key 时必须顺手改成「4 步完成部署」口径，改后要重跑 `node check_i18n.mjs` 保证 `MISSING_UNIQ=0`。

> 注：`用户端` 在检查命令中保留是因为历史代码可能残留；新增内容应使用 `用户端`（与仓库 user-server/user-web 对齐），禁用 `商户端/商家端/客户端`。
